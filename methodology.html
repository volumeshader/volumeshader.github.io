Volume Shader BM methodology

Benchmark v1.0 · Exact rules matter because benchmark numbers are only useful when the workload and measurement method are understood.

Render path

The renderer draws one full-screen triangle. The fragment shader constructs a view ray, intersects a bounded volume and samples along that ray. Each sample evaluates a power-8 Mandelbulb-style function and accumulates density front-to-back.

Render resolution

The canvas size is based on CSS size multiplied by device-pixel-ratio capped at 2, then multiplied by the preset render scale. A pixel cap of approximately 2.2 million limits very large render surfaces.

Timing rules

Frame timing uses requestAnimationFrame deltas. The first one second is treated as warm-up. Frames with a delta above one second are ignored. A timed run can be 30 seconds or 3 minutes; manual mode continues until stopped.

Metric formulas

MetricDefinition
Average FPS1000 × measured frame count ÷ total measured frame time.
1% low1000 ÷ the mean frame time of the slowest 1% of measured frames.
Minimum FPS1000 ÷ the longest measured frame time.
Maximum FPS1000 ÷ the shortest measured frame time.
Stability100 × (1 − standard deviation of frame times ÷ mean frame time), clamped to 0–100.

Stability is specific to this benchmark and is not a standard industry-wide rating.

Browser and GPU API

WebGL2 is used when available, with WebGL1 as a fallback. Browser GPU identification is shown only when the browser exposes the relevant debug renderer information.

Adaptive safety behavior

If two consecutive rendered frames each exceed roughly 1.5 seconds, the benchmark lowers the preset by one level, marks the run as adaptive and ends the active measurement. This prevents an extremely slow device from staying on an excessive workload indefinitely.

Reproducibility checklist

  1. Use the same benchmark version.
  2. Use the same preset and duration.
  3. Keep browser and power mode consistent.
  4. Note temperature and refresh-rate conditions.
  5. Repeat suspicious results.
