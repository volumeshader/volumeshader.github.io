The Origin of VSBM: Cznull, "Toxic Mushroom" (毒蘑菇), and Browser Benchmarking

Published by VolumeShader Technical Research Team // Updated for 2026

Every month, tens of thousands of users search for cznull, cznull github, cznull.github.io/vsbm, or 毒蘑菇 github. Behind these search queries lies one of the most fascinating viral technical phenomena on the web: the creation of a lightweight WebGL volumetric shader demo that accidentally became the world's most widely accessible browser-based GPU benchmark.

1. Who is cznull and What was vsbm.html?

The benchmark originated in the open-source GitHub Pages repository of developer cznull (cznull/cznull.github.io), specifically inside a standalone HTML file named vsbm.html (accessible publicly at cznull.github.io/vsbm).

When opening the original demo, an unstyled browser alert greeted visitors:

"trigonometric and inverse trigonometric functions test.
created by cznull@bilibili"

The author did not initially design it as a commercial benchmark or a corporate software suite. It was written as a pure trigonometric stressing experiment: how hard could a browser fragment shader push a GPU's floating-point arithmetic cores using only pure mathematical distance equations?

2. Why Chinese Communities Named it "Toxic Mushroom" (毒蘑菇)

As the link spread through Bilibili, Zhihu, and Chinese tech forums, users noticed two distinct traits:

  • Visual Appearance: The 8th-order Mandelbulb equation with cosine/sine normal mappings produces an organic, undulating shape resembling a luminous, psychedelic mushroom cap.
  • The "Toxicity": Passively cooled laptops and smartphones trying to render the scene at native resolutions immediately experienced 100% GPU utilization, sharp battery drain, and thermal throttling. Tech enthusiasts nicknamed it the "Toxic Mushroom test" (毒蘑菇显卡测试) because it was "poisonous" to underpowered GPUs.

3. Evolution into VolumeShader BM

While cznull's original page remains an iconic demonstration, it lacked essential instrumentation modern hardware testers require:

  • No numerical FPS counter or frametime monitoring.
  • No standardized timed benchmark sequence (to discard JIT warm-up time).
  • Fixed 1024×1024 CSS canvas scaling that distorted layout on modern mobile screens.
  • No 1% low frame time recording or thermal throttling alerts.
