Volumetric Raymarching & GLSL Shaders: The Math Behind VolumeShader BM

An Engineering Analysis of Distance Estimators & GPU Core Saturation

In traditional 3D graphics pipelines, scenes consist of polygon meshes transformed through vertex shaders and rasterized across screen pixels. In contrast, Volume Shader BM employs Sphere Tracing & Raymarching, a volumetric rendering technique where the camera casts a ray per pixel directly into an abstract mathematical distance field.

1. The Ray Marching Step Loop

Inside the fragment shader, each pixel establishes a ray origin origin and normalized direction dir. The ray marches forward in discrete spatial steps:

for (int k = 2; k < 1002; k++) { ver = origin + dir * (step * len * float(k)); v = kernal(ver); if (v > 0.0 && v1 < 0.0) { // Surface intersection detected! } }

With up to 1,000 steps per ray and over 1,000,000 pixels rendered on a 1024×1024 canvas, the GPU executes over one billion loop iterations every single frame.

2. Surface Refinement via Golden Ratio Bisection

Because discrete steps might skip small fractal crevices, VolumeShader BM utilizes a golden-ratio search solver. Once an intersection boundary is detected, the algorithm interpolates the ray position across 8 iterations using the golden ratio constants:

#define M_L 0.3819660113 // 1 - 1/phi #define M_R 0.6180339887 // 1/phi

This guarantees mathematical convergence onto the fractal shell without visual stepping artifacts or polygon aliasing.

3. Calculating Surface Normals Without Geometry

Since there are no geometric polygons or vertex normals in a raymarched shader, lighting normals must be approximated numerically using finite central differences. By sampling the kernel at small offsets along the camera's orthogonal axes (right, up, and forward), the shader calculates the gradient vector of the distance field to determine reflection angles.
