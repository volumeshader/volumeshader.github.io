Volumetric Shader and Raymarching Explained Simply

Updated 2026-10-21 · 8 min read · by the VolumeShader team

A volume shader test draws a detailed 3D shape without a single triangle. It does this with raymarching: every pixel sends a ray into space and asks a formula whether it hit something. This post explains the idea step by step, with the real code, in simple words.

The problem: drawing a shape with no triangles

Most 3D graphics are built from triangles. A model is a mesh. The GPU turns the triangles into pixels, which is fast and well understood. Now imagine a shape that is defined only by an equation, with endless fine detail. You cannot list its triangles, because there are too many and no flat faces at all. This is the case with a Mandelbulb fractal.

To draw such a shape, the program goes the other way around. It does not start with objects and ask which pixels they cover. It starts with each pixel and asks what that pixel can see. That idea is called raymarching, and it is the heart of every volume shader test.

What a fragment shader is

A shader is a small program that runs on the GPU. A fragment shader runs once for every pixel (more exactly, for every fragment) that the GPU draws. A GPU has thousands of small cores, so it runs the same short program for many pixels at the same time.

In this test, the page draws one rectangle that fills the canvas. The whole scene lives in the fragment shader. Every pixel runs its own raymarching loop, completely alone, and decides its own color. At 1024 by 1024, that is more than a million tiny programs per frame.

Raymarching in plain words

Picture a person walking through thick fog in a dark room, holding a stick. They take a small step forward, tap with the stick and ask: "Did I hit something?" If not, they take another step. When the stick finally hits a wall, they know where the wall is.

Raymarching does the same thing with math. For each pixel the program makes a ray that starts at the camera and points through that pixel. Then it moves along the ray in many small steps. At each step it asks the shape formula whether the point is inside the shape. When the answer changes from outside to inside, the surface is somewhere between the last two points.

Here is the simplified loop from the shader. The variable k counts the steps, and the shader allows up to about one thousand of them.

for (int k = 2; k < 1002; k++) {
  ver = origin + dir * (step * len * float(k));  // point on the ray
  v = kernal(ver);                               // ask the formula
  if (v > 0.0 && v1 < 0.0) {
    // the ray just went from outside to inside: surface found
  }
  v1 = v;
}

The function kernal (the spelling comes from the original code) returns a positive number when the point is inside the shape and a negative number when it is outside. That one function is the whole shape.

The Mandelbulb formula

The Mandelbulb is built by repeating one operation many times. Take a point, convert it to spherical coordinates, raise its distance to a power, multiply its angles, convert back, and add the starting point. Then repeat. Points that fly away quickly are outside the shape. Points that stay close are inside.

float kernal(vec3 ver) {
  vec3 a = ver;
  float b, c, d, e;
  for (int i = 0; i < 5; i++) {
    b = length(a);
    c = atan(a.y, a.x) * 8.0;
    e = 1.0 / b;
    d = acos(a.z / b) * 8.0;
    b = pow(b, 8.0);
    a = vec3(b * sin(d) * cos(c),
             b * sin(d) * sin(c),
             b * cos(d)) + ver;
    if (b > 6.0) break;
  }
  return 4.0 - a.x * a.x - a.y * a.y - a.z * a.z;
}

Let us read it slowly.

  • length(a) is the distance from the center.
  • atan and acos turn the position into two angles. The factor 8.0 is the "power" of the Mandelbulb, which gives it eight lobes of detail.
  • pow(b, 8.0) raises the distance to the eighth power.
  • The sin and cos terms turn the new distance and angles back into an x, y, z point. Adding ver keeps the starting point in the formula, and that is what makes the pattern repeat at every scale.
  • If the distance grows beyond 6, the point is clearly escaping, so the loop stops early.
  • The last line gives a positive number when the point stays close to the center, and a negative number when it has flown away.

Why this is so expensive

Let us count the work for the worst case at 1024 by 1024.

  • About 1,000,000 pixels, each with its own ray.
  • Up to about 1,000 steps per ray.
  • Up to 5 loops inside the formula at each step.
  • Five kinds of costly math functions in every loop: atan, acos, pow, sin and cos.

The worst case adds up to billions of formula loops per frame. In practice, many rays hit the shape early or miss it quickly, so the real number is lower, but the empty space around the shape is still checked step by step. This is why a phone can struggle at 1024 and a fast desktop card can stay smooth.

Functions like sine, cosine and power usually run slower on a GPU than plain addition and multiplication. Because the scene reads almost no memory, nothing hides that cost. The GPU spends nearly all its time calculating, so the result tells you about shader math speed. That is the reason this scene works well as a stress test.

Finding the surface more exactly

Steps are small, but not infinitely small. When the ray goes from outside to inside between two steps, the exact surface is somewhere in between. A shader could stop there and accept a rough answer, but that would show visible stripes on the surface.

So the shader refines the hit with a short search. It takes the point in the middle of the two, asks the formula again, and keeps the half that still contains the change. Repeating this eight times narrows the gap by a factor of about 256, which is enough to look smooth.

The code also handles thin parts that the ray might jump over. For this it uses a search based on the golden ratio. The two constants are about 0.382 and 0.618. They let the shader find a small peak between steps with few extra formula calls. You can find the same constants in the shader source.

#define M_L 0.3819660113   // 1 - 1/phi
#define M_R 0.6180339887   // 1/phi

How lighting works without triangles

A triangle has a known direction that it faces, called a normal. A fractal surface has none stored anywhere. The shader finds it by asking the formula a few more questions. It samples the formula at points a tiny distance to each side of the hit point, along three directions, and compares the values. The difference tells the shader which way the surface slopes, and that direction is the normal.

With a normal, the shader can calculate a simple reflection and add colors. That is why the surface of the Mandelbulb in the test looks shiny. All the light and color come from the formula too. There are no textures at all.

Is this really a volume shader?

The name suggests a volume, and that is how people use it. Strictly speaking, this test looks for a surface where the formula changes sign. A true volume renderer, like the ones used for clouds or medical scans, adds up small amounts of density along the ray. Both methods share the same idea of marching a ray through space and asking questions at each step. In everyday language, "volume shader" and "volumetric shader" are used for both. We use the common name so that people can find what they are looking for.

Frequently asked questions

What is a volumetric shader?+

It is a GPU program that draws a 3D shape or a cloud of density by sending a ray through space for every pixel and asking questions along the way, instead of drawing triangles.

What is raymarching?+

Raymarching is a way of finding what a pixel can see by moving a ray forward in small steps and checking at each step whether it has reached a shape.

What is a Mandelbulb?+

It is a 3D shape related to the Mandelbrot set. It is made by repeating a formula that uses spherical coordinates and a power, and it shows more detail the closer you look.

Why does this test use sine and cosine so much?+

The Mandelbulb formula needs angles, so it uses atan, acos, sin and cos in every loop. These functions are costly for a GPU, which makes the scene a good stress test.

Do I need to know programming to use the test?+

No. You only need to press start. The code in this post is for people who want to understand how it works.

What is the difference between raymarching and ray tracing?+

Ray tracing usually finds exact hits with triangles and often uses special hardware. Raymarching moves along the ray in steps and asks a formula about each point. Both use rays, but they solve the problem differently.

Can I change the shape?+

Yes. The preset menu offers other shapes, and the Shader Lab lets you edit the formula directly and see the result at once.
